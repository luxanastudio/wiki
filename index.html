Color Selection GUI

Players type /chatcolors (or /color) to open a 54-slot menu built with custom textured skull skins and color blocks:

  • Status Feedback: Unlocked colors show a green checkmark and active name preview. Locked colors show a red mark with the exact permission required.
  • Player Head Card (Slot 49): Displays your active chat color style and personal skin.
  • Reset Barrier (Slot 45): Clicking the red barrier unselects your active color, restoring default white chat.

Previews ([item], [i] & [inv])

Item Tooltip Hover Previews ([item] or [i])

Typing [item] or [i] in chat replaces the tag with the held item's localized name. Hovering over it in chat renders the client's native tooltip, displaying custom names, enchantments, lore lines, attributes, and attack speed:

Inventory Snapshot Previews ([inv])

Typing [inv] shares a clickable link in chat. Clicking opens a read-only snapshot GUI revealing the sender's main inventory, equipped armor, and offhand slots:

Chat Filter

Rule files in plugins/LuxChatColor/filters/ match prohibited words and regex patterns with automated escalation ladders (Warning at 3, Mute at 6, Kick at 9).

Welcome Messages & Multi-Slot Spaces

LuxChatColor includes a high-end join broadcast engine with Multi-Slot Spaces. Players can configure up to 20 distinct custom join messages, which automatically rotate at random with equal probability whenever they connect to the server!

Chance-Based Message Rotation: If a player configures 3 spaces, each join message has an exact 33.3% chance of being broadcast on join. The active probability is dynamically calculated and displayed in the player's profile card.

Key Features

  • Up to 20 Customizable Spaces: Unlocked via permissions luxchatcolor.welcomemsg.spaces.<1-20> or luxchatcolor.welcomemsg.spaces.*.
  • Configurable Server Ranks & Tiers: Fully customizable ranks in config.yml (Owner, Admin, VIP, Member, etc.) with custom prefix symbols (👑, ✦, ★), gradient borders, sounds, and fallback default messages.
  • Interactive 54-Slot GUI (/welcomemsg): Sleek, anti-slant menu featuring a real-time Player Profile Card (Slot 4), active enchanted books with live chances, an instant chat banner preview button (Slot 49), and a reset barrier (Slot 46).
  • Chat Prompt Editing: Left-clicking an unlocked space safely prompts the player in chat to type their custom join text with length limits and 'cancel' support.
  • First-Time Join Counter: Broadcasts a celebratory first-join announcement displaying the player's unique server join number (e.g., Player number = #42).
  • Rejoin Spam Cooldown: Configurable cooldown (default 30s) prevents players from spamming join broadcasts by rapidly reconnecting.

Rank Colour GUI

Running /rankcolor opens a 36-slot GUI featuring 3D colored orb heads powered by Minecraft-Heads. Clicking any unlocked head updates the player's personal rank color in LuckPerms without server restarts.

  • Prestige Dual-Color Rule: The rank title is bolded in the chosen color (e.g. &e&l[VIP]), and the player's username automatically matches the rank color without bold (&ePlayerName).
  • LuxChatColor Lore Engine: Lore cards feature authentic <smallcaps:rank color> headings, colorized bullet bars (&%code%| ▸), and dynamic status pills (&#FF0000&lLOCKED, <green><bold>SELECTED</bold>, &e&lCLICK HERE) with item glint on active selection.

Admin Management (/nameplateadmin)

Administrators have full command-line authority to inspect and assign nameplates to any player without GUI interaction:

  • /nameplateadmin set <player> <palette> - Assigns a specific gradient palette instantly.
  • /nameplateadmin clear <player> - Removes gradient styling, restoring the player's matching rank color.
  • /nameplateadmin list - Dumps all active palettes and preview tags to chat.
  • /nameplateadmin reload - Hot-reloads config.yml palettes and permissions.

TAB (NEZNAMY) Integration

LuxCustomRank turns every gradient palette into legacy hex codes and stores the finished name in LuckPerms user meta, so TAB can render exactly the same gradient in the player list. The plugin always writes a visible value – even before the player picks a colour or a nameplate – because TAB treats an empty placeholder in customtabname as an empty name, which makes players invisible in the tablist. On top of that, tab.auto-sync-seconds (default 10) re-checks every online player and re-saves the meta only when it is missing or stale, so a failed or too-early LuckPerms write self-heals.

LuckPerms meta key Contents
customtabname Finished name in legacy hex (&#RRGGBB): the chosen gradient, or the plain rank colour when no nameplate is selected.
customtagname Copy of the same value. TAB has no such property – it is only written for third-party plugins that read it. Do not point a TAB nametag at it.
lux_formatted_name Same value, exposed for chat and nametag plugins.
lux_nameplate_hex Same value, legacy hex form.
lux_rank_title, lux_rank_color, lux_nameplate, lux_nameplate_format Internal plugin state. Do not edit by hand.

1. Tablist name

TAB stores name formatting in groups.yml (or users.yml for a single player), not in config.yml. Add the meta placeholder to _DEFAULT_ so it applies to every player:

plugins/TAB/groups.yml 
_DEFAULT_:
  tabprefix: "%luckperms-prefix%"
  customtabname: "%luckperms_meta_customtabname%"
  tabsuffix: ""

PlaceholderAPI note: TAB's built-in LuckPerms placeholders only expose %luckperms-prefix% and %luckperms-suffix%. Reading meta requires the LuckPerms PlaceholderAPI expansion (%luckperms_meta_customtabname%). Watch the spelling: it is luckperms_meta_<key> with underscores, never %luckperms-meta-customtabname%. Without PlaceholderAPI, keep customtabname: "%player%" – the tablist stays readable, it just shows no gradient.

Name still invisible without a colour? That means the placeholder resolved to nothing. Check in this order:
  1. /luxcustomrankadmin debug <player> – prints the stored customtabname, the expected name and whether they match. A non-empty value here means the plugin side is fine and TAB is overriding it.
  2. Run /tab player <player> customtabname (no value) to clear a per-player override, and check per-world: / users.yml for a higher-priority empty customtabname.
  3. Run /papi parse me %luckperms_meta_customtabname% – if it prints the raw placeholder, the LuckPerms expansion is missing or the key is misspelled.

2. Name above the head (overhead nametag)

This is not controlled by customtabname. TAB draws the overhead nametag with scoreboard teams, and teams can only add a prefix and a suffix around the real username – the name itself cannot be changed, and the name colour can only be one of the 16 legacy colours. A gradient above the head is impossible with TAB's teams alone.

LuxCustomRank therefore ships its own overhead renderer: nametag.overhead: display spawns a TextDisplay above every player (Paper 1.19.4+) and draws the exact same gradient that the tablist uses. It is a full Adventure component, so RGB works.

plugins/LuxCustomRank/config.yml 
nametag:
  overhead: display   # vanilla = TAB flat colour, display = real gradient

  display:
    height: 2.25                 # blocks above the player's feet
    update-interval-ticks: 2     # lower = smoother, more packets
    view-range: 1.0
    line-width: 400
    shadow: true

Because TAB/Minecraft would still draw its own nametag underneath, hide it in TAB while keeping teams for sorting and collision:

plugins/TAB/config.yml 
scoreboard-teams:
  enabled: true
  # true = TAB hides the vanilla nametag, LuxCustomRank draws the gradient one
  invisible-nametags: true
  • Alternative (no display entities): set scoreboard-teams.enabled: false and nametag.custom-name: always. LuxCustomRank then writes the gradient onto the player entity, but TAB sorting, collision and nametag visibility stop working.
  • Flat colour only: keep nametag.overhead: vanilla. TAB tints the name with the last colour code of tagprefix, so set tagprefix: "%luckperms-prefix%" (LuxCustomRank already ends its prefix with a colour code). No RGB, no gradient.
  • Third-party: CustomNameplates, UnlimitedNameTags, DisplayNameTags or NotJustNameplates do the same job as the display mode.
plugins/TAB/config.yml 
tablist-name-formatting:
  enabled: true

scoreboard-teams:
  # Only for the "no display entities" alternative above:
  # false = let LuxCustomRank write the gradient onto the player entity
  enabled: true

3. Chat

LuxCustomRank also sets player.displayName() to an Adventure component that contains the same gradient. Whether chat shows it depends entirely on the chat plugin's format string: a format that uses the display name component (for example %player_displayname% from the Player expansion, or the player's Adventure display name) renders the gradient; a format that only uses the raw username (%player_name%) cannot, because the raw name has no formatting at all. Change the chat format to the display-name placeholder and the gradient appears there too.

If you were given a single nametag: block with prefix/suffix/customtabname, it is the same idea – current TAB versions keep those keys in groups.yml as tabprefix, customtabname and tabsuffix.

  • Dynamic Username Injection: Palette templates automatically replace %name% and %player% with the player's actual in-game username with zero configuration.
  • Paper & Spigot Direct Tablist API: LuxCustomRank also updates player.playerListName() and player.displayName() in real-time on join and palette change, so servers without TAB still see the change.
  • Zero Hologram Overhead by default: 100% native client rendering with zero entity ticking. The optional nametag.overhead: display mode adds one lightweight text display per player so the overhead name can use the real gradient.

Custom Titles

Players with luxcustomrank.prefix can type /customrank &b[VIP] or /customrank &6[KNIGHT] to assign their own personal prefix.

Anti-Abuse Filter

Custom prefixes are strictly validated against character length limits and the banned-words list to prevent staff impersonation.
